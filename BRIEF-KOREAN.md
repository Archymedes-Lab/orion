# ORION in Korean

**What it is.** Korean becomes ORION's second full language, in both the Expo app (`src/`) and the Next.js web app (`web/`). When someone switches to 한국어, everything ORION says changes, not just the menus. That covers every visible string, placeholder, button, empty state, error, toast, accessibility label and page title. It covers the text the decision engine writes (reasons, "what would change the answer", the follow-up questions, confidence and robustness wording, the Aftermath steps, good and hard turns, early signs, check-ins). It covers what the AI models write (option and factor labels, the explanation, the Aftermath wording), the exports (PDF, Excel, archive), the legal pages, and the web app's interactive 3D Aftermath (its badges, readouts, time cursor, summary sentence and screen-reader table). Dates and numbers follow the language too. Only proper names stay as they are (ORION, Jev, Archymedes, Stripe, Paypack), along with what the person typed themselves. Behaviour, layout, scoring and data do not change; English stays the source language and the default.

**How it works.** All text goes through `src/i18n` (`@orion/i18n/...` from `web/`). Write the English in place and wrap it: `t("Decide now")`, with `{name}` placeholders for values: `t("{n} options compared", { n })`. The English text is the key into the Korean dictionary. Each area has its own file under `src/i18n/ko/` (`engine`, `aftermath`, `decide`, `account`, `app`, `server`, `web`), and the keys must match the English exactly. Always translate whole sentences. Never glue fragments together with `+` or template strings, and never build a sentence from a translated word: Korean word order is different, so a sentence with a value in it is one `t()` call with a placeholder. For lists use `listPhrase()`. For dates and numbers use `intlLocale()`. Text in a table or constant built when a module loads is marked with `msg("…")` and passed through `t()` where it is shown, because the language can change at runtime. Code that must not rely on the current language uses `tIn(locale, …)` (Next server components, anything per-request on the server). Synchronous engine calls on the server are wrapped in `withLocale(locale, () => …)`. Expo screens remount when the language changes (`app/_layout.tsx`), so `t()` at render is enough. Components that must update without a remount use `useLocale()`. `LanguageSwitch` is the one control for choosing; it names each language in itself. Ids, enum values, stored keys and anything compared in code are never translated, only what is shown. A saved decision keeps the language it was made in.

**How it should read.** The Korean is written by someone who designs Korean products, not run through a translator. Use polite, warm 해요체, short and plain, matching ORION's English voice: give the answer first, no jargon, never scold. Use natural Korean word order and particles, never English phrasing word for word. Keep the glossary consistent everywhere: decision 결정, option 선택지, what matters / factor 중요한 것 (short label: 기준), priorities 우선순위, analysis 분석, trade-offs 장단점, Aftermath 그 이후 (heading "그 이후의 모습"), check-in 체크인, private mode 비공개 모드, sign in 로그인, sign up 회원가입, account 계정, plan 요금제, beta 베타, ORION's call ORION의 판단, too close to call 우열을 가리기 어려워요, history 기록, insights 인사이트, profile 프로필. Buttons are short verbs (결정하기, 다시 시도, 저장). Percentages, numbers and currencies stay as they are. Placeholders such as `{n}` survive unchanged, and each `{name}` goes where Korean grammar wants it. Where a particle depends on the word before it (이/가, 을/를, 은/는, 으로/로), write the sentence so it reads correctly whatever fills the placeholder, for example with a colon or a noun ending ("기준: {factor}").

**The models and the server.** Every API call carries `X-Orion-Lang: en|ko`. The Expo client sends it from `src/ai/http.ts`, and the web proxy (`web/app/api/orion/[...path]`) must forward it. The server validates it (anything else means `en`) and passes it to every AI function: parse, score, triage, explain, Aftermath, and the business playbook prompts. For `ko`, each prompt's instructions add one rule. Every user-facing text field (titles, option and factor labels, sentences, likely, goodTurn, hardTurn) is written in natural Korean 해요체, while JSON keys, ids and enum values stay exactly as the schema says, and triage still copies candidate text exactly (the candidates are already Korean). Jev and System One keep their typed questions; only what reaches the person is in Korean. The local fallbacks must work in Korean too. The offline parser understands Korean questions ("A 아니면 B", "A 할까 B 할까", "A vs B", "A 또는 B", "할까 말까") and gives Korean labels. The question bank, local explanations and the Aftermath fallback all write Korean. Safety is not negotiable. The crisis classifier must recognise Korean distress and danger language (for example 자살, 죽고 싶, 자해, 살고 싶지 않, 끝내고 싶), and the support path must give Korean help in Korean: 자살예방상담전화 109, 정신건강위기상담전화 1577-0199, and 112 / 119 in an emergency.

**Web, and when it is done.** `web/` uses the same `src/i18n`. The language lives in an `orion_locale` cookie, which the switch sets. Server components read it and use `tIn(locale, …)`. Client components use `t()` with `useLocale()`, after setting the module language from the cookie on first load. The switch sits in the marketing header and the app rail. `<html lang>` follows the language, page metadata is translated, and Hangul is rendered with Noto Sans KR next to the existing faces. Text drawn inside the three.js scene is translated like any other, and the Expo app's Futures chart and Aftermath likewise. PDFs show Hangul through the non-embedded Adobe-Korea1 CID font (`HYGoThic-Medium`, `UniKS-UCS2-H`) whenever a run of text is outside WinAnsi, so English reports stay byte-for-byte as they are. It is done when `tests/i18n.test.js` passes. That test finds every `t`, `tIn` and `msg` literal in `src/`, `server/` and `web/` and checks each one has Korean that keeps its placeholders, with no leftover keys. The repo-wide `bun run check` must pass and `web/` must build. Screens are then looked at in both languages, and with 한국어 chosen nothing visible is still in English apart from the proper names above and the person's own words.
